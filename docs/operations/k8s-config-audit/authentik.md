# authentik (authentik)

**Chart version:** 2026.8.0 — current upstream latest, zero drift
**Audit date:** 2026-08-28

Identity provider / SSO, used as OIDC/forward-auth for grafana, headlamp, portainer, gatus, goldilocks, alertmanager, and prometheus (all already audited elsewhere in this series). Config lives entirely in `k3s/infrastructure/configs/authentik/` — `k3s/applications/authentik/` only contains legitimate migration/ leftover artifacts, same pattern already established for other apps.

## Findings

### 🔴 Clear actionable gap

**An imperative, git-untracked debug pod (`curl-oidc`, image `curlimages/curl:latest`) has been sitting in the `authentik` namespace since 2026-08-26** — 3 days old at audit time, not declared anywhere in this repo (confirmed via repo-wide grep), and using the `:latest` tag this repo's own Renovate config explicitly disables tracking for. Completed/harmless (`STATUS: Completed`, not consuming resources), but it's GitOps drift — cluster state that doesn't match git — and should be deleted (`kubectl -n authentik delete pod curl-oidc`) rather than left to accumulate.

### 🟢 Well-configured, no action needed

- Chart pinned at `2026.8.0` — confirmed current upstream latest, zero drift, no open Renovate PR needed.
- **The documented prior outpost-token incident (`authentik-outpost-token-must-be-autogenerated` memory) has not regressed** — checked live outpost pod logs directly rather than trusting the config alone: it's successfully loading all 3 proxy-provider applications (`alertmanager-provider`, `goldilocks-provider`, `prometheus-provider`), returning correct 302 redirects, refreshing on interval with no `"embedded": true` marker anywhere in current logs — the exact failure signature from the prior incident is absent.
- All 9 credential/secret values are wired via `valuesFrom` Secret refs, not hardcoded; `authentik-secret.sops.yaml` is genuinely SOPS-encrypted.
- Blueprint ConfigMap correctly references OIDC client secrets via `!Env` indirection — no hardcoded secrets sitting in the plaintext-readable ConfigMap.
- PostgreSQL persistence correctly migrated to `longhorn` with a clear, accurate comment describing the full migration history, consistent with the same pattern already verified working in the kopiur audit.
- Resource requests/limits set on server/worker/postgresql, all with sane headroom.
- `headlamp-oidc-rbac.yaml`'s ClusterRoleBinding (OIDC group `homelab-admins` → `cluster-admin`) is appropriately scoped to a named admin group, not "any authenticated user" — reasonable for a single-operator homelab, and the comment explicitly flags it as an adjustable, deliberate choice.
- No restarts on any core pod (server, worker, postgresql, outpost) — all fully stable; not applicable to the kine/leader-election pattern (issue #355).

### 🟡 Worth knowing, not clearly actionable

- **`authentik-outpost` (the hand-written raw Deployment, not part of the Helm chart) has zero `securityContext` and implicitly mounts the `default` ServiceAccount's API token** — same category as the tdarr finding earlier in this audit: the proxy container never calls the Kubernetes API, so `automountServiceAccountToken: false` would be a free fix. Unlike tdarr, this one also has no `runAsNonRoot`/capability-dropping at all — a fully custom manifest with no upstream-chart excuse.
- **The Helm chart's own `server`/`worker` pods also render `securityContext: {}`** — confirmed the chart genuinely exposes this as a real values knob (3 separate `securityContext: {}` defaults in `helm show values`), so like opentelemetry-collector and tempo, this is a fixable local gap, not an upstream limitation.
- The chart provisions a `Role`/`ClusterRole` granting authentik broad CRUD on `secrets`/`services`/`configmaps`/`deployments` (its native "Kubernetes" outpost-integration type) — confirmed via `kubectl get deploy -l app.kubernetes.io/managed-by=goauthentik.io` that **no such integration is actually in use**; this cluster's outpost is deployed by hand instead. This RBAC appears to be inert chart-default overhead rather than something actively exercised — same pattern as MetalLB's idle BGP backend and nvidia-device-plugin's idle MPS daemon found earlier in this audit, just with slightly more sensitive permissions (secrets CRUD) sitting unused.
- Postgres image tag (`17.11-bookworm`) currency is inconclusive from this shell — the tag itself resolves, but a Docker Hub tag listing check only surfaced up through `17.9-bookworm`, likely a pagination/sort artifact rather than genuine drift. Not asserting a finding either way.
